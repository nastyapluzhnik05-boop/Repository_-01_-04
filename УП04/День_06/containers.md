# Работа с контейнерами
## Контейнер hello-world
Выполнена команда:
sudo docker run hello-world

Появилось сообщение Hello from Docker!
Тестовый контейнер успешно запустился, вывел сообщение и завершил работу

Проверены списки образов и контейнеров:
sudo docker images
sudo docker ps
sudo docker ps -a

Образ hello-world появился в списке образов, а контейнер после завершения получил статус Exited

## Контейнер nginx
Для запуска веб-сервера выполнена команда:
sudo docker run -d --name up04-web -p 127.0.0.1:8080:80 nginx:alpine
Контейнер успешно запустился

Проверка:
sudo docker ps
curl -I http://127.0.0.1:8080
Контейнер имел статус Up. Сервер вернул ответ HTTP/1.1 200 OK

Для просмотра журналов использовались команды:
sudo docker logs up04-web
sudo docker logs --tail 10 up04-web
В журналах отображались обращения к веб-серверу

Также проверена остановка и повторный запуск контейнера:
sudo docker stop up04-web
sudo docker ps -a
sudo docker start up04-web
После повторного запуска сервер снова отвечал на запросы

## Ответы на вопросы самостоятельной работы

1. Чем образ отличается от контейнера?
Образ - это шаблон приложения, а контейнер - запущенный экземпляр этого образа

2. Почему hello-world завершился, а nginx продолжает работать?
Hello-world выводит сообщение и завершает работу. Nginx должен постоянно работать и обрабатывать запросы

3. Что означает -d?
Запуск контейнера в фоновом режиме

4. Что означает --name up04-web?
Задаёт контейнеру имя up04-web

5. Зачем нужен порт 8080:80?
Он связывает порт 8080 Ubuntu с портом 80 внутри контейнера, через который работает nginx

6. Почему указан адрес 127.0.0.1?
Чтобы веб-сервер был доступен только с самой виртуальной машины

7. Как увидеть логи контейнера?
С помощью команды docker logs с указанием имени контейнера

8. Чем stop отличается от rm?
stop останавливает контейнер, но сохраняет его. rm удаляет остановленный контейнер
